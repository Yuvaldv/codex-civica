      BASE_URL = "https://www.legislation.gov.uk"
      USER_AGENT = "CodexCivica (https://github.com/Yuvaldv/codex-civica)"
      CRAWL_DELAY = 5

    Implement, in this order:

    1. `make_session() -> requests.Session` — a `requests.Session()` with
       `session.headers.update({"User-Agent": USER_AGENT})`. Do not rely on a per-request header;
       set it once on the session so it is impossible to issue a request without it.

    2. `fetch_raw(session, uri: str) -> tuple[bytes, str] | None` — GET
       `f"{BASE_URL}/{uri}/data.xml"` with `timeout=REQUEST_TIMEOUT`, wrapped in the same
       `try/except (requests.HTTPError, requests.ConnectionError, requests.Timeout)` retry loop as
       `fetch_laws.py:paginate` (MAX_RETRIES attempts, RETRY_DELAY between retries of the SAME item —
       this is independent of and shorter than CRAWL_DELAY). `response.raise_for_status()` after
       every attempt. On success return `(response.content, response.url)` — `response.url` is the
       resolved URL after any redirect. On exhausted retries, log the error and return `None`.

    3. `parse_gates(xml_bytes: bytes) -> dict | None` — `etree.fromstring(xml_bytes)`, read
       `root.get("NumberOfProvisions")` and `root.get("DocumentURI")`. Determine stub status: reject
       (return `None`) if `NumberOfProvisions` is `None` or `"0"`, OR if
       `root.find(".//leg:Primary/leg:Body", NS) is None and root.find(".//leg:Primary/leg:Schedules", NS) is None`
       (also check `leg:Secondary` as a fallback parent, since some item types use it). On rejection,
       log at WARNING level with the exact reason (missing NumberOfProvisions vs `="0"` vs no Body/
       Schedules) and the URI — this log line is Gate 1's audit trail per 08-RESEARCH.md.
       On acceptance, extract and return a dict: `document_uri`, `doc_status` (from
       `.//ukm:DocumentStatus`, `@Category` attribute — if absent or not exactly `"revised"`, this is
       a hard failure per Gate 2: log an ERROR and return `None`, do NOT write a file for a
       non-revised or unlabelled document), `year` (from `.//ukm:Year`, `@Value`), `number` (from
       `.//ukm:Number`, `@Value`), `title` (from `.//dc:title` — add `"dc": "http://purl.org/dc/elements/1.1/"`
       to NS for this one lookup), `number_of_provisions` (int).

    4. `derive_slug(item_type: str, year: str, number: str) -> str` — `f"{item_type}-{year}-{number}"`.
       Never derive from the request URI path (08-RESEARCH.md: pre-1963 regnal paths must not leak
       into the slug).

    5. `fetch_item(session, uri: str, item_type: str) -> dict` — orchestrates one item:
       call `fetch_raw`; if `None`, return a manifest row with `status="fetch_failed"`,
       `xml_path=None`, `skip_reason="request failed after retries"`. Otherwise call `parse_gates` on
       the bytes; if `None` (either gate failed), return a manifest row with `status="pdf_only"` (Gate
       1) or `status="wrong_version"` (Gate 2 — non-revised/unlabelled doc_status), `xml_path=None`,
       and `skip_reason` set to the logged reason string. **A gate failure never writes to XML_DIR.**
       If both gates pass: derive the slug, write the raw XML bytes to
       `XML_DIR / f"{slug}.xml"` (create `XML_DIR` with `mkdir(parents=True, exist_ok=True)` first;
       skip the actual GET+write if `(XML_DIR / f"{slug}.xml").exists()` already — idempotent re-run,
       matching `fetch.py:download_pdf`'s convention — but still populate the returned manifest row
       from the gate-parsed metadata of the cached file), and return the full manifest row with
       `status="fetched"`, `xml_path` set to the file's path relative to the project root, and
       `fetched_at` set to `datetime.now(timezone.utc).isoformat()`.

    6. `load_manifest()` / `save_manifest(rows)` — same idiom as `fetch.py:123-142`: manifest on disk
       is a JSON list; `save_manifest` writes `json.dump(rows, f, ensure_ascii=False, indent=2)`
       after `DATA_DIR.mkdir(parents=True, exist_ok=True)`.

    7. `main() -> int` — `logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s")`;
       create the session; iterate `BATCH` in order, calling `fetch_item` for each, appending to a
       `rows` list, and sleeping `CRAWL_DELAY` seconds **between** items (skip the sleep after the
       last item — no wasted wait at the end of the run, and skip it entirely for an item whose file
       already existed on disk before this run, since no network request was made for it). After the
       loop, `save_manifest(rows)`. Print a one-line summary: counts of `fetched`/`pdf_only`/
       `wrong_version`/`fetch_failed`. Return `0` if every item's status is `"fetched"`, else `1`
       (validation errors must never be silently ignored — CLAUDE.md).

    `if __name__ == "__main__":` — `raise SystemExit(main())`, matching the repo's exit-code
    contract (no argparse needed yet; this script takes no arguments in this phase — the batch is
    hardcoded, not parameterised, per the ≤10 constraint).

    ASVS V7 (command injection): no `shell=True` anywhere, N/A here (no subprocess). ASVS V12 (path

    so no path-traversal surface exists; still, do not interpolate `uri` (attacker-adjacent — it is a
    hardcoded constant here, but treat it as if it could vary) directly into a filesystem path.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pipeline to external service (legislation.gov.uk) | Untrusted remote XML crosses into local parsing (`lxml.etree.fromstring`) and local disk writes |
| pipeline to local filesystem (`data/raw/uk/`) | Gitignored, but still a real write surface — slugs must not admit path traversal |
| fair-use policy compliance | A crawl-delay violation or missing User-Agent risks a block on the project's IP, affecting all pipelines, not just this one |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | XML parsing of remote content | mitigate | `lxml.etree.fromstring` is not `eval`/`pickle`; no XSLT, no external entity resolution requested (lxml's default `resolve_entities` is off for `fromstring` without an explicit permissive parser) — ASVS V5 |
| T-08-02 | Denial of service (against the remote service) | Request cadence | mitigate | Mandatory 5s `CRAWL_DELAY` between items, sequential only, no concurrency; identifying `User-Agent` set once on the session, never omitted (ASVS: fair-use compliance is the threat model here, not a formal ASVS category, but ties to V7-style "don't let this code become an attack tool") |
| T-08-03 | Tampering (integrity) | Version confusion — enacted vs revised text published as if current | mitigate | Gate 2 hard-rejects any non-`"revised"` `doc_status`; `grep -c '/enacted' pipeline/uk/fetch_uk.py` asserted 0 in Task 1's acceptance criteria — the enacted path is never constructed, not merely unused |
| T-08-04 | Tampering (integrity) | Bodyless stub published as if it were the law | mitigate | Gate 1 hard-rejects `NumberOfProvisions=0`/absent or missing Body+Schedules; rejection is logged with reason and recorded in the manifest, never silently dropped (CLAUDE.md: validation errors must never be silently ignored) |
| T-08-05 | Information disclosure / path traversal | `XML_DIR / f"{slug}.xml"` | mitigate | `slug` is built only from parsed `year`/`number` (numeric-shaped, from a namespace-qualified XML attribute) and a fixed `item_type` string from the hardcoded `BATCH` list — never from unsanitised remote content or the raw request URI (ASVS V12) |
| T-08-SC | Tampering | pip installs | accept | Zero new runtime dependencies (`requests`, `lxml` already present) |
</threat_model>
