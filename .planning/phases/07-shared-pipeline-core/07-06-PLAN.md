    copying the bodies verbatim from 07-PATTERNS.md.

    `render_frontmatter(lines: list[str]) -> str` joins with newlines the sequence: the literal
    `---`, then each element of `lines`, then the literal `---`, then an empty string. That trailing
    empty element is what makes the returned string end with a newline and no extra blank line — it
    is load-bearing, not cosmetic. Use the docstring from 07-PATTERNS.md, which states explicitly
    that callers own field selection, ordering, and value formatting and that this function owns only
    the block shape.

    `quote(value: str) -> str` wraps the value in double quotes after replacing each embedded double
    quote with a backslash-escaped double quote.

    Explicitly do NOT:
      - use `yaml.safe_dump` or any PyYAML call. PyYAML 6.0.3 is installed and would re-quote
        strings, reorder keys, line-wrap, and emit `null` instead of `~` — a guaranteed failure of
        the `dab1887e…` SHA gate. The normal "don't hand-roll YAML" instinct is inverted in a
        byte-identity refactor.
      - add validation, schema checking, key ordering, type coercion, or a dict-to-YAML converter.
        These functions are two lines each by design.
      - apply `quote()` inside `render_frontmatter`. Quoting happens at the caller's value sites.

    `quote()` is intentionally unused by `reconcile.py` in this phase — it exists for the future
    non-Israel caller and for the country-blindness probe in 07-07. `reconcile.py` already escapes at
    the value site (lines 122 and 127 both call the double-quote replace), so adopting `quote()`
    there would double-escape. Leave those lines completely untouched.

    Boundary constraint unchanged: stdlib imports only; no Israel module, no `.env`, no secret.

    Write a throwaway check (not committed) asserting: rendering two lines produces a 4-line string
    ending in a newline whose first and third-from-last lines are `---`; rendering an empty list
    produces exactly two fence lines; `quote` on a plain value adds only surrounding quotes; and
    `quote` on a value containing a double quote backslash-escapes it.
  </action>
